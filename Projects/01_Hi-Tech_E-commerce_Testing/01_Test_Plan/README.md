<p>This project focuses on manual testing of the Hi-Tech e-commerce website. The purpose is to evaluate the website's functionality, user interface, navigation, and main shopping workflows from an end-user perspective.</p>

<p>Проект посвящён ручному тестированию интернет-магазина Hi-Tech. Цель — проверить функциональность сайта, пользовательский интерфейс, навигацию и основные процессы покупки с точки зрения пользователя.</p>

<h2>🎯 02. TEST OBJECTIVES — ЦЕЛИ ТЕСТИРОВАНИЯ</h2>

<p>The main testing objectives are:</p>

<ul>
<li>Verify the correct operation of the main website functionality.</li>
<li>Check product catalog and navigation.</li>
<li>Verify product search and filtering functionality.</li>
<li>Check product information displayed on product pages.</li>
<li>Verify shopping cart operations.</li>
<li>Check registration and login functionality, if available.</li>
<li>Evaluate the checkout process and order creation, if available.</li>
<li>Identify and document defects.</li>
<li>Verify the consistency of information displayed to the user.</li>
</ul>

<p><strong>Основные цели:</strong></p>

<ul>
<li>Проверить работу основных функций сайта.</li>
<li>Проверить каталог товаров и навигацию.</li>
<li>Проверить поиск и фильтрацию товаров.</li>
<li>Проверить информацию в карточках товаров.</li>
<li>Проверить работу корзины.</li>
<li>Проверить регистрацию и авторизацию, если функции доступны.</li>
<li>Проверить оформление заказа, если функция доступна.</li>
<li>Обнаружить и задокументировать дефекты.</li>
<li>Проверить согласованность отображаемой информации.</li>
</ul>

<h2>▶️ 06. ENTRY CRITERIA — КРИТЕРИИ НАЧАЛА ТЕСТИРОВАНИЯ</h2>

<p>Testing can begin when:</p>

<ul>
<li>The website is accessible.</li>
<li>The main website functionality has been reviewed.</li>
<li>The initial testing scope has been defined.</li>
<li>Test scenarios and test cases have been prepared.</li>
<li>The test environment has been identified.</li>
</ul>

<p>Тестирование начинается после изучения сайта, определения объёма проверок и подготовки тестовой документации.</p>

<h2>🏁 07. EXIT CRITERIA — КРИТЕРИИ ЗАВЕРШЕНИЯ ТЕСТИРОВАНИЯ</h2>

<p>Testing can be considered complete when:</p>

<ul>
<li>All planned test cases have been executed or marked as Blocked.</li>
<li>Test results have been documented.</li>
<li>Identified defects have been recorded.</li>
<li>Available test evidence has been collected.</li>
<li>A Test Summary Report has been prepared.</li>
</ul>

<p>Тестирование считается завершённым после выполнения запланированных проверок, документирования результатов и подготовки итогового отчёта.</p>

<h2>⚠️ 08. RISKS AND LIMITATIONS — РИСКИ И ОГРАНИЧЕНИЯ</h2>

<ul>
<li>Some functionality may require user registration — некоторые функции могут требовать регистрации.</li>
<li>Certain operations may require real customer data — отдельные операции могут требовать реальные данные.</li>
<li>Payment operations may not be available for testing — платёжные операции могут быть недоступны для тестирования.</li>
<li>Website functionality may change during testing — функциональность сайта может изменяться во время тестирования.</li>
<li>Some test scenarios may depend on external services — некоторые сценарии могут зависеть от внешних сервисов.</li>
<li>Testing is limited to the available user interface and accessible functionality — тестирование ограничено доступным интерфейсом и функциональностью.</li>
</ul>
